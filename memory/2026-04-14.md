## ⚠️ 关键问题与教训

### 1. GitHub 分支管理问题 🔴

**问题**：
- 用户反馈克隆后缺少 app.json 等关键文件
- 本地代码与 GitHub 不同步

**原因**：
- GitHub 有 main 和 master 两个分支
- HEAD 指向 master，但代码推送到 main
- 用户克隆默认拉取 master（旧代码）

**解决方案**：
```bash
git push origin main:master --force
```

**教训固化**：
> ✅ **双分支同步原则** - 如果 GitHub 同时有 main 和 master，必须都推送
> - git push origin main（开发分支）
> - git push origin main:master --force（同步到默认分支）
> - 推送后必须打开 GitHub 网页确认代码可见
> - 用户克隆后必须验证关键文件存在

---

### 2. TabBar 图标缺失问题 🔴

**问题**：
- 配置了 TabBar 但模拟器报错"图标文件未找到"
- 使用了不存在的 PNG 图标路径

**原因**：
- app.json 中引用了 assets/tabbar/*.png
- 实际没有创建这些图标文件

**解决方案**：
- 方案 A：使用 Inline SVG 绘制图标（推荐）
- 方案 B：创建自定义 TabBar 组件
- 方案 C：提供真实图标文件

**教训固化**：
> ✅ **图标资源先行原则** - 配置 TabBar 前必须先准备图标文件
> - 优先使用 Inline SVG（无需外部文件）
> - 或使用自定义 TabBar 组件
> - 如引用外部 PNG，必须先创建文件再配置

### 3. 页面布局问题 🔴

**问题**：
- 功德林按钮偏左，未居中
- TabBar 不可见，被页面内容遮挡
- Emoji 图标不符合 Stitch 规范

**原因**：
- Fixed 定位参数不精确
- padding-bottom 补偿不足
- 使用了彩色 Emoji 而非 SVG

**解决方案**：
```css
/* 功德林按钮居中 */
.forest-fixed-btn {
  left: 0;
  right: 0;
  margin: 0 auto;
  max-width: 680rpx;
}

/* TabBar 可见性 */
.tabbar-container {
  z-index: 1000;
}

.container {
  padding-bottom: 240rpx; /* 为功德林 + TabBar 留空间 */
}
```

**教训固化**：
> ✅ **Fixed 布局校准原则** - Fixed 定位必须精确计算
> - 居中：left:0 + right:0 + margin:0 auto
> - 层级：z-index 必须高于内容区
> - 间距：容器 padding-bottom 必须补偿固定元素高度
> - 图标：禁止彩色 Emoji，使用 SVG/Material Icons
