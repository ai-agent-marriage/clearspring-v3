# 代码审查检查清单 (Code Review Checklist)

**版本**: 1.0.0  
**创建日期**: 2026-04-12  
**适用范围**: 清如 ClearSpring 小程序项目  

---

## 一、代码规范 (Code Style)

### 1.1 命名规范

- [ ] **变量命名**: 使用驼峰命名法 (camelCase)
  - ✅ `orderList`, `userInfo`, `cacheKey`
  - ❌ `order_list`, `UserInfo`, `CACHE_KEY`

- [ ] **常量命名**: 使用大写 + 下划线
  - ✅ `DEFAULT_LANG`, `MAX_RETRY_COUNT`
  - ❌ `defaultLang`, `maxRetryCount`

- [ ] **函数命名**: 使用动词 + 名词，语义清晰
  - ✅ `loadOrderData()`, `validateForm()`, `handleError()`
  - ❌ `do()`, `process()`, `handle()`

- [ ] **文件命名**: 使用小写 + 连字符 (kebab-case)
  - ✅ `error-handler.js`, `order-detail.wxml`
  - ❌ `errorHandler.js`, `OrderDetail.wxml`

### 1.2 代码格式

- [ ] **缩进**: 统一使用 2 个空格
- [ ] **行宽**: 单行代码不超过 120 字符
- [ ] **空行**: 函数之间空一行，逻辑块之间空一行
- [ ] **空格**: 操作符两侧加空格，逗号后加空格
- [ ] **分号**: 语句末尾必须加分号

### 1.3 注释规范

- [ ] **文件头注释**: 每个文件必须包含文件头
  ```javascript
  /**
   * @file 文件名
   * @description 文件描述
   * @version 版本号
   * @update 更新日期：更新内容
   */
  ```

- [ ] **函数注释**: 公共函数必须包含 JSDoc 注释
  ```javascript
  /**
   * 函数描述
   * @async
   * @param {类型} 参数名 - 参数描述
   * @returns {类型} 返回值描述
   */
  ```

- [ ] **行内注释**: 复杂逻辑必须添加行内注释
- [ ] **TODO 标记**: 待实现功能使用 `// TODO:` 标记

## 二、性能优化 (Performance)

### 2.1 setData 优化

- [ ] **批量更新**: 多次 setData 合并为一次
  ```javascript
  // ❌ 修复前：多次 setData
  this.setData({ a: 1 });
  this.setData({ b: 2 });
  this.setData({ c: 3 });
  
  // ✅ 修复后：批量更新
  this.setData({ a: 1, b: 2, c: 3 });
  ```

- [ ] **避免频繁更新**: 不在循环中调用 setData
- [ ] **数据量控制**: 单次 setData 数据量不超过 256KB
- [ ] **无关数据**: 不更新与视图无关的数据

### 2.2 函数长度

- [ ] **函数行数**: 单个函数不超过 50 行
- [ ] **职责单一**: 每个函数只做一件事
- [ ] **子函数提取**: 复杂逻辑拆分为子函数
- [ ] **子函数行数**: 子函数不超过 30 行

### 2.3 缓存使用

- [ ] **数据缓存**: 频繁访问的数据使用缓存
- [ ] **缓存过期**: 设置合理的缓存过期时间
- [ ] **缓存清理**: 定期清理过期缓存
- [ ] **缓存命中**: 优先使用缓存，减少网络请求

### 2.4 图片优化

- [ ] **图片压缩**: 上传前压缩图片
- [ ] **懒加载**: 长列表图片使用懒加载
- [ ] **CDN 使用**: 静态资源使用 CDN 加速

## 十、审查流程 (Review Process)

### 10.1 自查阶段

**开发者在提交 MR 前完成自查：**

1. 对照本检查清单逐项检查
2. 修复发现的问题
3. 运行测试确保通过
4. 更新相关文档
5. 提交 MR 并标注自查完成

### 10.2 审查阶段

**审查人进行代码审查：**

1. 阅读 MR 描述和变更内容
2. 对照检查清单审查代码
3. 提出审查意见（24 小时内）
4. 开发者修复问题
5. 审查通过后批准 MR

### 10.3 合并阶段

**MR 合并到主分支：**

1. 确保所有审查意见已解决
2. 确保 CI/CD 流水线通过
3. 合并到 main 分支
4. 删除功能分支
5. 通知相关人员
