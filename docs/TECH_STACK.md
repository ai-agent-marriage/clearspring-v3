## 🎯 核心技术决策

### 决策 1：小程序端 - 坚持微信原生开发

**背景**：PRD V2.0 明确要求音频后台播放、锁屏控制、高性能渲染

**决策内容**：使用微信原生小程序框架（WXML + WXSS + JavaScript）

**技术栈详情**：
- **基础库版本**: 2.19.0+（支持音频后台播放、分包加载）
- **开发工具**: 微信开发者工具 Stable Build
- **语言**: JavaScript (ES6+)，暂不引入 TypeScript（降低学习成本）
- **样式**: WXSS + 自定义 CSS 变量（Stitch 设计系统）
- **组件化**: 原生 Component + 自定义组件库

**关键优势**：
1. ✅ **音频播放**：`wx.createInnerAudioContext()` 原生支持后台播放、锁屏控制
2. ✅ **性能**：首屏渲染时间 < 1s，包体积 < 4MB（符合微信限制）
3. ✅ **兼容性**：微信版本 ≥ 8.0.0，覆盖 99% 活跃用户
4. ✅ **审核**：原生开发最符合微信审核规范，降低驳回风险

**风险评估**：
- ⚠️ **代码复用**：无法直接复用到其他平台（但 PRD 无多端需求）
- ⚠️ **TypeScript**：暂不支持，后续可逐步迁移

**接口分工**：

| 接口类型 | 部署位置 | 理由 |
|---------|---------|------|
| 音频播放、梵音统计 | 火山云 Express | 长连接、高频访问 |
| 订单管理、支付回调 | 火山云 Express | 复杂事务、 webhook |
| 用户登录、注册 | 火山云 Express | 会话管理、JWT |

1. ✅ **成本优化**：高频接口用固定成本服务器，低频用按量计费云函数
2. ✅ **性能平衡**：Express 处理复杂业务，云函数处理轻量任务
3. ✅ **风险分散**：单一平台故障不影响全系统
4. ✅ **复用资产**：现有代码无需重构，降低开发成本

### 决策 4：数据库 - 混合存储（MySQL + 云数据库）

**背景**：PRD 要求订单事务支持、小程序端免鉴权访问

**决策内容**：核心业务用 MySQL，小程序端用云数据库

**数据分布**：

| 数据类型 | 存储位置 | 理由 |
|---------|---------|------|
| 用户信息、订单、结算 | MySQL | 事务支持、复杂查询 |
| 梵音收听记录、打卡记录 | 云数据库 | 小程序直连、高频写入 |
| 禅理内容、物种库 | MySQL + 云数据库同步 | 读多写少，双端缓存 |
| 日志、操作记录 | 云数据库 | 低成本、易扩展 |

**数据同步策略**：
- **实时同步**：用户信息、订单状态（通过云函数触发）
- **定时同步**：禅理内容、物种库（每日凌晨同步）
- **单向同步**：MySQL → 云数据库（避免数据冲突）

## 🔧 关键实现方案

### 数据同步机制

混合架构（MySQL + 微信云数据库）中的数据同步采用以下方案：

**架构设计**：
```
小程序端 → 微信云数据库（实时读写）
           ↓
      云函数（数据同步）
           ↓
    火山云 MySQL（主数据库）
```

**同步策略**：
- **正常流程**：云函数实时同步（毫秒级）
- **兜底流程**：定时任务每 30 分钟全量比对一次
- **告警机制**：同步失败超过 10 次，发送飞书告警

**数据一致性保障**：
1. 唯一索引防重：MySQL 端设置唯一索引
2. 乐观锁：使用 `updated_at` 字段检测冲突
3. 重试机制：同步失败自动重试 3 次
4. 死信队列：重试失败进入死信队列，人工处理

📖 **详细文档**: [DATA_SYNC_GUIDE.md](./DATA_SYNC_GUIDE.md)

### 故障切换方案

火山云服务器故障时的高可用保障：

**架构设计**：
```
用户请求
  ↓
Nginx（负载均衡 + 健康检查）
  ↓
主节点：火山云服务器（101.96.192.63:3000）
备用节点：微信云函数（自动接管）
```

**故障检测**：
- Nginx 健康检查：每 10 秒检查一次，连续 3 次失败判定为故障
- 应用层心跳检测：每 30 秒检查一次 API 健康状态

**切换流程**：
1. 监控脚本检测到主节点故障
2. 发送飞书告警（立即）
3. Nginx 自动路由到备用节点（30 秒内）
4. 备用节点（云函数）接管服务（只读模式）
5. 运维人员修复主节点
6. 手动切换回主节点

**降级策略**：
- 故障期间，只读接口正常（查看订单、查看证书）
- 写接口降级（下单、登记）提示"系统维护中"
- 引导用户使用小程序基础功能（梵音、禅理）

📖 **详细文档**: [FAILOVER_GUIDE.md](./FAILOVER_GUIDE.md)

### 监控告警配置

全面的监控告警体系：

**监控指标**：

| 类别 | 指标 | 阈值 | 告警级别 |
|------|------|------|----------|
| 服务器 | CPU 使用率 | > 80% | P1 |
| 服务器 | 内存使用率 | > 80% | P1 |
| 服务器 | API 响应时间 | > 2 秒 | P1 |
| 服务器 | 错误率 | > 5% | P1 |
| 业务 | 订单间隔 | > 2 小时 | P2 |
| 业务 | 支付失败率 | > 10% | P1 |
| 数据库 | 连接数使用率 | > 80% | P1 |
| 数据库 | 慢查询 | > 5 个/分钟 | P2 |

**告警渠道**：
- **P0**（电话 + 飞书）：服务器宕机、数据库不可用、支付失败
- **P1**（飞书）：CPU/内存过高、响应时间过长、错误率过高
- **P2**（飞书）：慢查询增多、上传失败、审核失败

**监控面板**：
- 工具：Grafana + Prometheus
- 面板：服务器资源、Node.js 进程、MySQL 数据库、业务指标

📖 **详细文档**: [MONITORING_SETUP.md](./MONITORING_SETUP.md)
